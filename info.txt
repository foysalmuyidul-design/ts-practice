Step 1: Initialize the Project in CMDRun these commands in your command prompt to create your folders, initialize your package manager, and install TypeScript:

# 1. Create and enter your project folder
mkdir my-ts-project
cd my-ts-project

# 2. Create the folders you planned for
mkdir src dist

# 3. Initialize package.json (creates default settings)
npm init -y

# 4. Install TypeScript as a development tool
npm install -D typescript @types/node

# 5. Generate your tsconfig.json file
npx tsc --init


Step 2: The Top Settings to Tweak ImmediatelyOpen your newly generated tsconfig.json file. It will look like a giant wall of text because of all the helpful comments. Use your code editor's search tool (Ctrl + F) to find and change only these specific lines:Look for "target": "es2016" → Change it to "target": "es2022" (or higher) to use modern JavaScript.Look for // "rootDir": "./" → Remove the // and change it to "rootDir": "./src".Look for // "outDir": "./" → Remove the // and change it to "outDir": "./dist".Finally, scroll all the way to the very bottom of the file (outside the main curly brace block of compilerOptions) and paste these two lines to keep your compilation scope clean:


  }, // This is the closing brace for compilerOptions
  "include": ["src/**/*"],
  "exclude": ["node_modules", "dist"]
}


Step 3: Add Convenience ScriptsOpen your package.json file. Find the "scripts" section and update it to look like this so you don't have to keep typing long paths into CMD:

"scripts": {
  "build": "tsc",
  "start": "node dist/index.js",
  "watch": "tsc --watch"
}


Step 4: Test it out!Create a file named index.ts inside your src folder.Add a simple test line: console.log("TypeScript works!");In your CMD window, run:

npm run build


Look at your project sidebar—you will see a brand new, beautifully compiled index.js file living directly inside your dist folder. You can run it instantly using npm start.Would you like to add a tool like ts-node-dev or nodemon next?These tools can automatically recompile AND restart your app every single time you hit save, giving you a seamless coding workflow without touching the terminal again.

Let’s set up ts-node-dev. It combines the speed of compilation with an automatic app restarter, making it the absolute best tool for a modern TypeScript development workflow.Unlike nodemon + ts-node (which can feel sluggish because it restarts the entire TypeScript compiler process on every save), ts-node-dev shares a single compilation process across restarts. It is incredibly fast.Here is how to get it running in your new project:Step 1: Install the ToolRun this command in your CMD terminal to add it as a development tool:

npm install -D ts-node-dev


Step 2: Update Your package.json ScriptsOpen your package.json file, look for the "scripts" section, and add a new dev command. It should look like this:

"scripts": {
  "build": "tsc",
  "start": "node dist/index.js",
  "dev": "ts-node-dev --respawn --transpile-only src/index.ts"
}


What do those flags mean?--respawn: Keeps watching the files for changes even if your script crashes due to an error.--transpile-only: Tells the tool to skip full type-checking during development restarts. This is what makes it blazing fast. (Don't worry, your code editor will still show you squiggly red lines if you make a syntax mistake, and npm run build will still do a full strict check later!).Step 3: Run Your New Development ServerNow, instead of manually compiling or running separate watch windows, simply type:

npm run dev

Because of this, it completely removed the old programmatic JavaScript APIs that older tools like ts-node and ts-node-dev depended on. if i make another ts file like problem1.ts then how to run it


To run a specific file like problem1.ts inside your src folder, you have two quick ways to do it depending on whether you want it to watch for changes or just run once.Option 1: Run it once immediatelyIf you installed tsx from the previous step, you can run any individual file directly via your terminal using npx:

npx tsx src/problem1.ts

Option 2: Run it with "Watch Mode" (Restarts on save)If you are actively working on problem1.ts and want it to re-run every time you save, add the watch flag:

npx tsx watch src/problem1.ts

Pro-Tip: Make it a quick npm shortcutIf you plan on working on multiple problem files (like problem1.ts, problem2.ts, etc.) and don't want to type out the full paths every time, you can add a flexible shortcut script to your package.json:Open package.json and add a script named "file":

"scripts": {
  "build": "tsc",
  "start": "node dist/index.js",
  "dev": "tsx watch src/index.ts",
  "file": "tsx watch"
}

Now, you can pass the file path dynamically directly through npm run like this

npm run file src/problem1.ts

(Note: If you are using Git Bash or standard CMD, you might need to use a double dash like npm run file -- src/problem1.ts to pass the argument safely).Are you setting up this project to solve coding challenges (like LeetCode or Advent of Code) where you will have many separate problem files?If so, I can show you a clean way to organize your folder structure so your files don't clutter up a single directory!

That is completely normal! tsx watch runs your TypeScript code directly in memory for fast development. It deliberately does not output any JavaScript files to your dist folder.Think of it like a live preview server—it executes your logic instantly without wasting time writing files to your hard drive on every single save.How to get files into distWhen you are ready to generate the actual compiled JavaScript files inside your dist folder, you need to run your build script:

npm run build


(This triggers the official TypeScript compiler tsc, which reads your tsconfig.json and outputs the permanent files into dist).

how to upload it in githubTo upload your TypeScript project to GitHub, you need to initialize a Git repository, make sure you don't accidentally upload your heavy node_modules folder, and then push it to GitHub.Here is the exact step-by-step process using your command prompt:Step 1: Create a .gitignore file (CRITICAL)Before doing anything with Git, you must tell it to ignore folders that shouldn't be tracked (like node_modules, which can be reinstalled anytime, and your generated dist folder).In the root of your project folder (ts-practice), create a new file named .gitignore (make sure it starts with a dot).Open the file and paste these lines inside it


node_modules/
dist/
.env

Step 2: Initialize Git and Commit Your CodeRun these commands in your terminal to prepare your project locally:

# 1. Initialize an empty local Git repository
git init

# 2. Stage all your project files (it will ignore node_modules and dist automatically)
git add .

# 3. Create your first save point (commit)
git commit -m "Initial commit: setup TS project with src folder"

# 4. Rename your main branch to "main" (the GitHub default)
git branch -M main

Step 3: Create a Repository on GitHubGo to github.com and log into your account.Click the "+" icon in the top-right corner and select New repository.Give your repository a name (e.g., ts-practice).Leave everything else blank (Do NOT check the boxes for adding a README, .gitignore, or license, since we already made our own).Click Create repository.Step 4: Link and Push Your CodeGitHub will show you a page with a few lines of code under the heading "…or push an existing repository from the command line".Copy and paste those exact two commands into your command prompt. They will look similar to this:

# Link your local project to your online GitHub repository
git remote add origin https://github.com

# Push your code to GitHub
git push -u origin main

Refresh your GitHub browser page, and you will see your clean src folder, package.json, and tsconfig.json uploaded safely online!Did you run into any authentication errors (like a login or permission prompt) while trying to push the code?If you don't have Git installed or configured with your name/email yet, let me know and I can show you how to quickly set that up!

change in 1 file and m beside it's nameThat "M" beside your file name is a visual status indicator from Git (visible in your code editor, like VS Code).It stands for Modified.It means Git has successfully tracked that file before, and it notice that you have made new changes to it since your last commit.How to update GitHub with your new changeWhenever you see that "M" and you are ready to upload your updated code to GitHub, run these three quick commands in your terminal:

# 1. Stage the modified file (updates the file in Git's staging area)
git add .

# 2. Lock in your new changes with a descriptive message
git commit -m "Update problem1 file with new solution"

# 3. Push the new commit to GitHub
git push origin main
